# Map: Agentic STRIDE Threat-Modeling Workflow

Label: `wayfinder:map`
Tickets live in `.wayfinder/tickets/` as child issues. A ticket is claimed by setting its `assignee:` frontmatter; open+unassigned+unblocked = frontier.

## Destination

A production-quality STRIDE threat-modeling service in this repo: Python, Google ADK graph-based multi-agent workflow, self-owned container on Cloud Run behind Ping-authenticated endpoints. Front-end submits semi-structured text one-shot, receives a job handle, polls/streams until a structured JSON report (per-element threats + severity + mitigations, traceable to input elements) is ready. Shipping includes a golden-case eval suite in CI.

## Notes

- Language: Python. Always consult the `python-style` skill when writing Python and the `owasp-security` skill for security-relevant code.
- **Execution is carried into this map** (destination is a full production build): once design tickets close, implementation tickets graduate from the fog.
- Per-agent Vertex model selection is a hard requirement (e.g., Flash for extraction, stronger models for analysis). Token/context optimization is a standing preference.
- Prompts and skills load from a directory of files via this repo's own loader interface — one implementation, being renamed to a neutral `MarkdownLoader` with `SkillLoader` kept as an alias (no external PromptLoader exists to mirror; see [Obtain existing PromptLoader interface](tickets/011-prompt-loader-interface.md)).
- **Deterministic decisions belong in code; models are used only for judgement decisions not easily handled by deterministic code.** Standing principle across the whole application — split every node's checks into mechanical (validators, FunctionNode bookends, lints) and judgement (what the prompt addresses).
- Commits: no AI attribution trailers. User prefers concise communication.

## Decisions so far

- Deployment boundary — Cloud Run (own container; Agent Engine rejected: IAM-only endpoint auth can't front Ping, logging constrained to stdlib/Cloud Logging paths, Agent Identity pre-GA).
- Input shape — hybrid: semi-structured front-end text normalized by a cheap extraction agent into a canonical system model.
- Interaction model — one-shot with async delivery (job handle, poll/stream progress; no mid-run user input).
- Output — structured JSON: per-element STRIDE threats with severity + mitigations, traceable to input flows/endpoints.
- Quality bar — golden-case eval suite in CI; cases bootstrapped from OWASP Threat Model Cookbook + internal systems, SME-blessed once.
- [Research: multi-agent quality patterns for threat modeling](tickets/001-research-quality-patterns.md) — generator–critic wins; skip debate and mixed MoA; STRIDE-per-element fan-out + one strong-tier critic pass, ~2-4x token budget. Findings on `research/quality-patterns`.
- [Research: ADK graph features and per-agent Vertex model config](tickets/002-research-adk-graph.md) — ADK 2.5.0 Workflow Runtime: directed graph with conditional edges/JoinNode fan-in, per-node model strings, `include_contents='none'` + state templating for context scoping, SSE streaming, `get_fast_api_app()` on Cloud Run. Findings on `research/adk-graph`.
- [Domain model: canonical system representation](tickets/003-domain-model-system-representation.md) — classic five DFD element types, typed-slug IDs, flat trust zones with derived boundary crossings, fixed security-relevant attributes with explicit `unknown` + assumptions list, controlled asset-tag enum, mechanical validity gate with one repair pass. Glossary in `CONTEXT.md`.
- [Decide graph topology and quality pattern](tickets/004-graph-topology-quality-pattern.md) — six parallel STRIDE-category analysts + one grounded critic pass (verdicts, dedupe, severity calibration); no debate/voting; static ADK Workflow: extract → validate/repair → prepare → 6 analysts → join → critic → router → assemble, with deterministic FunctionNode bookends and a reserved REVISE route.
- [Implement System Model schema and validator](tickets/012-implement-system-model-schema.md) — shipped as `stride_service` package (Pydantic 2, src layout, uv): five element types + typed-slug ID helpers, derived `boundary_crossings()`, mechanical gate returning structured `ValidationIssue`s, `parse_and_validate()` for the repair pass; 29 tests green.
- [STRIDE report schema and severity model](tickets/005-report-schema.md) — likelihood×impact with matrix-derived band (DREAD rejected); per-threat critic-calibrated confidence; verdicts with unknown-refs; `rejected_threats` audit array; self-contained payload embedding the System Model; job/nodes/summary metadata. Prototype on `prototype/report-schema`.
- [Skills-as-SME design and injection](tickets/006-skills-sme-design.md) — two-axis library: six per-analyst category skills + shared severity rubric, mechanical domain-pack hook (empty in v1); five fixed sections per skill, exemplars stay in prompts; repo Markdown baked into image via PromptLoader-mirroring SkillLoader; full text in system instruction with CI token caps; critic gets rubric + mechanically assembled boundary digest.
- [Per-agent Vertex model tier assignment](tickets/007-model-tier-assignment.md) — two named tiers, pinned version strings (no aliases): flash → extract/repair, pro → six analysts + critic; versioned config file with env-var override on tier strings only; no cross-tier auto-degrade, upgrades eval-gated.
- [Front-end API contract (async jobs, Ping auth)](tickets/008-api-contract.md) — custom `/v1` job API wrapping the ADK Runner (stock ADK routes non-prod only): POST /v1/jobs → poll GET /v1/jobs/{id} + SSE /events → GET /v1/jobs/{id}/report; lifecycle queued→running→completed|failed|rejected with ValidationIssues on rejection; RFC 9457 errors; Ping JWT dependency, owner-only reads (404); storage/TTL deferred.
- [Implement report schema in stride_service](tickets/014-implement-report-schema.md) — shipped as `stride_service.report`: all ticket-005 models with the fixed severity matrix (`derive_severity_level()` exposed for evals), enforced verdict shapes and threat-ID category letters, self-containment invariants (refs resolve, crossings derived, summary consistent), `Job.status` aligned to `completed` per the 008 contract; 31 tests, suite 60 green. Unblocks [Implement job API in stride_service](tickets/018-implement-job-api.md).
- [Author v1 STRIDE category skills and severity rubric](tickets/015-author-skill-files.md) — shipped `skills/stride/*.md` (six, filenames matching `StrideCategory` literals) + `skills/shared/severity_rubric.md` (mirrors the shipped `SEVERITY_MATRIX`) + empty `skills/domains/`; fixed H2 headings `Scope | Applicability | Threat Patterns | Guardrails | Mitigations` — the exact strings ticket 016's lints and critic-digest extraction must target; token estimates well under caps.
- [Implement SkillLoader, boundary-digest assembly, and CI skill lints](tickets/016-implement-skill-loader.md) — shipped as `stride_service.skills`: fail-closed `SkillLoader` (directory-of-files interface, made canonical by [Obtain existing PromptLoader interface](tickets/011-prompt-loader-interface.md)), mechanical critic digest from the six `## Scope` sections, analyst/critic composition in cacheable stable-first order, CI lints enforcing filenames, exact headings, and token caps; suite 102 green. Analyst skill text ≈ 2.2K tokens, critic ≈ 2.3K — cacheable-prefix facts for [Context optimization strategy](tickets/010-context-optimization.md).
- [Implement model-tier config in stride_service](tickets/017-implement-model-config.md) — shipped as `stride_service.model_tiers` + `config/model_tiers.toml`: canonical LLM node names fixed (`extract`, `repair`, `analyst/<category>` ×6, `critic` — exported `LLM_NODES`), fail-closed loader with `resolve_model(node)`, `STRIDE_MODEL_FLASH`/`STRIDE_MODEL_PRO` overriding tier strings only, pinned-suffix rule rejecting `-latest`/aliases; suite 129 green.
- [Implement job API in stride_service](tickets/018-implement-job-api.md) — shipped as `stride_service.jobs` (lifecycle state machine, append-only `seq`-numbered event log, `JobStore`/`PipelineRunner` seams with in-memory + stub implementations), `stride_service.auth` (`PingJwtVerifier`, RS256-only, all rejections collapsed to one generic error), and `stride_service.api` (`create_app()` with injectable seams, the five `/v1` routes + unauthenticated `/healthz`, RFC 9457 errors, 404-not-403 owner-only reads); 54 tests, suite 183 green. Storage backend and the real ADK Runner stay behind their seams; local HTTP verification recipe in `.claude/skills/verify/SKILL.md`.
- [Obtain existing PromptLoader interface](tickets/011-prompt-loader-interface.md) — the external PromptLoader isn't available and won't be; the shipped `SkillLoader` (root-relative POSIX names sans `.md`, lazy read, no templating, fail-closed `SkillNotFoundError`/`SkillFormatError`) is canonical rather than provisional, and prompt loading follows the same shape. Unblocks [Author agent prompts and few-shot exemplars](tickets/013-agent-prompts-exemplars.md), which now owns the choice of a mirroring `PromptLoader` vs reusing `SkillLoader` against a `prompts/` root.
- [Author agent prompts and few-shot exemplars](tickets/013-agent-prompts-exemplars.md) — skill is *what to know*, prompt is *what to do with this job's input*; one templated `analyst.md` + six exemplar files (not six prompts); four fixed headings `Role | Input | Procedure | Output` with no JSON in `## Output`; three exemplars per category (canonical, second-order, unknown-conditional) over one shared miniature system model, lint-parsed through a new `DraftThreat` model that carries the seven analyst-owned fields; critic runs five judgement steps in one call over all six analysts' drafts with mechanical checks moved to code; `extract` defaults to `unknown` and records every inference, `repair` sees the original input text and never invents. Loader renamed to neutral `MarkdownLoader`, `SkillLoader` aliased. Graduated tickets 019, 020, 021.
- [Author agent prompt files and category exemplars](tickets/019-author-prompt-files.md) — shipped `prompts/{extract,repair,analyst,critic}.md` + `prompts/exemplars/*.md` ×6: four exact H2s, prose-only `## Output` (no JSON anywhere in it), one shared five-flow payment exemplar system in `analyst.md`'s `## Input` whose `trust_zone` values are boundary **IDs**, four deliberate `unknown`s carrying the six unknown-conditional exemplars, and lane contrast taught in prose over same-flow pairs (S-02/E-02, T-01/I-01). All 18 exemplars parse as seven-field `DraftThreat`s citing only IDs in that system, verified by script; every file well under cap (worst-case analyst instruction ≈4.7K). Unblocks [Implement prompt loading, DraftThreat, and prompt lints](tickets/020-implement-prompt-loading.md), whose lint spec is the ticket's verification script.

## Not yet specified

- Observability: wiring the custom logging library, tracing/OTel across graph nodes.
- Error handling in the graph: partial results, retries, timeouts, poison inputs.
- CI/CD pipeline and Cloud Run deployment details (Ping middleware specifics follow org patterns).
- Job store backend and retention TTL (report JSON at rest; contract reserves 404-after-expiry — see [Front-end API contract](tickets/008-api-contract.md)). The `JobStore` seam and an in-memory implementation now exist, so this is a choice of backend behind a settled interface.
- Cost/quota controls per model tier.
- Technology-domain skill packs: authoring + the pack-selection rule table in `prepare` — graduate when evals show domain-specific recall gaps.
- Implementation build-out tickets — graduate once topology, report schema, and contracts close. (System Model schema graduated and shipped via [Implement System Model schema and validator](tickets/012-implement-system-model-schema.md); report schema graduated and shipped via [Implement report schema in stride_service](tickets/014-implement-report-schema.md); skill files authored and shipped via [Author v1 STRIDE category skills and severity rubric](tickets/015-author-skill-files.md); loader/lints shipped via [Implement SkillLoader, boundary-digest assembly, and CI skill lints](tickets/016-implement-skill-loader.md); model tiering shipped via [Implement model-tier config in stride_service](tickets/017-implement-model-config.md); API contract graduated and shipped via [Implement job API in stride_service](tickets/018-implement-job-api.md). Prompt content, prompt loading, and graph assembly all graduated on the close of [Author agent prompts and few-shot exemplars](tickets/013-agent-prompts-exemplars.md), as tickets 019, 020 and 021 — no implementation fog remains.)
- Per-job context budget: the token caps enforced in CI cover only the static instruction side. The System Model and the six analysts' drafts scale with input and are unguarded — oversize surfaces as a loud Vertex context-length error, never a silent partial analysis. The critic is the pressure point, seeing all six analysts' output in one call. Belongs to [Context optimization strategy](tickets/010-context-optimization.md).

## Out of scope

- Per-analysis human review flow (pending_review states, reviewer queue/roles) — deliver reports as-is, labeled AI-generated; a later effort if wanted.
- Vertex AI Agent Engine migration — rejected for this effort (see Decisions).
- Front-end implementation — this effort owns the service contract only.

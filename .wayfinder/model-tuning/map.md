## Destination

Both model classes the workflow uses (`flash`, `pro`) carry their own ADK/GenAI `GenerateContentConfig` tuning params, loaded fail-closed from the pinned config and applied **per node** in the graph. The pinned file stays canonical — eval and production read the same values — every run **stamps the effective per-tier params** for provenance, tuning is done by an **eval sweep that promotes a winner into the file**, and env override survives only as a **recorded, eval-gated escape hatch**. Shipped end-to-end with offline tests and docs. The tuned *values* and any live sweep run are out of scope (no Vertex here); this effort ships the mechanism, `temperature = 0` stays the default.

- [Research: ADK 2.5 tuning params — the GenerateContentConfig surface, per-class applicability, and which ADK owns](tickets/01-research-adk-tuning-params.md) — v1 set: **offer** `temperature`/`top_p`/`seed` (seed best-effort, not a reproducibility guarantee) plus per-tier class-guarded `thinking_budget` (flash 0–24,576 with 0=off, pro 128–32,768 with 0 a 400); **reserve** `candidate_count` (= the deferred Self-MoA lever)/`top_k`/`max_output_tokens`/penalties; **forbid** `response_schema` (ADK *raises*)/`response_mime_type`/`stop_sequences`/`http_options`. ADK forwards the config verbatim to Vertex; `top_k` is a float. Findings on `research/model-tuning-params` (`c92c29b`).
- [Decide provenance stamping and the env-override / eval-gate policy](tickets/03-provenance-and-override-policy.md) — record **both** clear per-tier sampling values **and** a derived fingerprint = `sha256(served model, tier sampling)`, **per node** on `NodeRun` (clear values once, top-level per-tier); model+sampling bound into **one generation-identity hash** keyed on the *served* model so build-drift is visible. v1 **ships** the env escape hatch **`STRIDE_SAMPLING_{TIER}_{PARAM}`**, **offered params only** (temperature/top_p/seed/class-guarded thinking), validated like the file, fail-closed; reserved/forbidden env vars **raise**; overrides captured by the fingerprint — reintroducing what decision 15 banned *because* the gate now makes drift visible. Gate = a checked-in **blessed-fingerprint manifest** (sweep promotion writes both it and `sampling.toml`) + a pure offline `certify(report_fingerprints, manifest)`; report carries **raw fingerprints only**, certification computed in the **eval/CI layer**, never silently trusted. `http_options` stays forbidden on the override surface (no un-fingerprinted path).
- [Decide the per-tier tuning config schema and sampling.toml migration](tickets/02-config-schema-migration.md) — **key by tier** (`[tiers.flash]`/`[tiers.pro]`, reusing `model_tiers.toml`'s node→tier map); the file carries the **full commented decoding surface** (temperature/top_p/top_k/seed/max_output_tokens/candidate_count/penalties/thinking), each param pinned to its default with a one-line comment — reversing the old "absent = model default" for explicit self-documentation. `temperature = 0.0` pinned; `candidate_count = 1` reserved (loader **fail-closes if ≠ 1** — the Self-MoA lever); `thinking` a per-tier mixed scalar (`"off"`|`"auto"`|int) resolved class-legal in the loader. Contract-breaking params (`response_schema` etc.) stay out, named in a "why-absent" block. **Hard cutover** to `version = 2`, no v1 shim. `SamplingConfig` → tier-keyed; graph gets an injected **`resolve_sampling: node → TierSampling`** sibling to `resolve_model`. **Judge out of this effort.** The default *numbers* were not in ticket 01 — sourcing them is [ticket 04](tickets/04-per-class-decoding-defaults.md).
- [Research: authoritative Gemini 2.5 per-class decoding defaults (flash vs pro)](tickets/04-per-class-decoding-defaults.md) — most per-class defaults are **not publishable**: `top_p`/`top_k`/penalties are model-dependent with no rendered constant (Google's Vertex tables are JS-only), so they land **UNVERIFIED** — the build-out **leaves them unset** rather than inventing numbers. Verified: `max_output_tokens` model max **65,536** (both classes; unset = uncapped to ceiling); `seed` no numeric default, best-effort; penalties effective default `0.0`. **Correction to ticket 02's `thinking` comment:** dynamic allocation is **not** the unset default — unset applies the model's preset per-class budget; dynamic needs explicit `thinking_budget = -1`. Findings on `research/model-tuning-defaults` (`90615ef`).

## Out of scope

- **Running a live tuning sweep and choosing the "best" per-tier values** — needs live Vertex, the same boundary the whole live-eval chain sits behind on the [design map](../map.md). This effort ships the mechanism and offline machinery only; defaults are unchanged (`temperature = 0`), and the numbers are a future eval effort.
- **Any move off Gemini 2.x** — already ruled out on the design map; per-class applicability is decided against `gemini-2.5-flash` / `gemini-2.5-pro` only.
- **Fingerprinting the effective resilience / `http_options`** — ruled out by [the provenance/override ticket](tickets/03-provenance-and-override-policy.md). The sampling override surface *forbids* `http_options` (per ticket 01), so this effort adds no un-fingerprinted path; but the pre-existing `RunConfig.http_options → config/resilience.toml` override (`basic.py:82-83`) is **not** folded into the generation-identity fingerprint. `resilience.toml` is a separate pinned config (tickets 038/039) the map keeps apart; making a timeout override visible in provenance is resilience's own future concern, not this hash.
- **The eval judge adopting the per-tier tuning shape** — ruled out by [the schema ticket](tickets/02-config-schema-migration.md). `evals/config/judge.toml` stays a separate pinned config: it's single-tier (`pro` only, per-class shape buys nothing) and deliberately decoupled from `sampling.toml` (fixed measuring stick vs. config-under-test). Any judge-decoding change is a re-baselining event under ticket 009 decision 13, not part of this mechanism.

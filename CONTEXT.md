# Context

Glossary for the STRIDE threat-modeling service. The canonical system model is the extraction agent's output and every downstream agent's input.

## Glossary

- **System Model** — the canonical, structured representation of the system under analysis, produced by the extraction agent from semi-structured front-end text. The single source all analyst agents consume.
- **Element** — any node or edge in the System Model. Exactly five types (classic DFD-based STRIDE-per-element taxonomy): External Entity, Process, Data Store, Data Flow, Trust Boundary.
- **External Entity** — an actor outside the system's control: users, third-party systems.
- **Process** — running code or a component that transforms data.
- **Data Store** — where data rests: databases, buckets, queues-at-rest.
- **Data Flow** — a directed connection carrying data between two elements. One flow per interaction; direction = who initiates, the response rides implicitly. An independent reverse-direction interaction (webhook, push) is its own flow.
- **Trust Boundary** — a named trust zone (flat, no nesting): network zones, auth boundaries, privilege levels. Every External Entity, Process, and Data Store belongs to exactly one zone via `trust_zone`.
- **Boundary Crossing** — a derived fact, never extracted: a Data Flow crosses a boundary iff its endpoints' zones differ. The highest-signal STRIDE input, computed mechanically so it cannot contradict the model.
- **Asset** — something worth protecting. Not an element type: modeled as tags on Elements from a small controlled vocabulary (`credentials`, `pii`, `financial`, `health`, `secrets`, `business-critical-data`, `availability-critical`, `reputation`; config-extendable). Feeds impact scoring and skill selection; system-specific detail lives in the element's own name/description.
- **Unknown** — a legal attribute value meaning the input neither stated nor allowed inference of a fact. Analysts treat an unknown security control as unverified, never as present or absent. Uncertainty a speaker *voices* — a hedged value ("I think it's OIDC") or an admitted gap ("no idea") — is also `unknown`, not a value and not an **Assumption**: speaking about a fact is not stating it. Their words are kept verbatim in the element's `notes`, which is what distinguishes a gap someone probed from a topic nobody raised. Two **Sources** that disagree land here too wherever the attribute can hold it: equal weight means a disagreement is recorded rather than adjudicated, so the value is `unknown` and both claims are quoted verbatim in `notes` beside their labels. What `notes` carries either way is context for the question a needs-info **Verdict** asks — never evidence for a **Threat**, and never weight on a rating: an unknown attribute rates identically whether someone hedged about it, two people contradicted each other, or nobody raised it at all.
- **Assumption** — a value extraction inferred with a stated basis. Recorded on the System Model's top-level assumptions list (assumption, element ID, basis) as well as in the attribute itself. Unknown = not stated; Assumption = inferred on the record. Never a silent guess — and never a *speaker's* guess: the basis is what extraction inferred from what the input supports, so a hedge is never one. That distinction is invisible downstream if it is got wrong, because an analyst weighs an assumption's value as read from the text. One case arises from the schema rather than from the text: where two **Sources** disagree on an attribute that *cannot* hold `unknown` — a `trust_zone`, an External Entity's `kind`, a Data Flow's endpoints — extraction must still emit a legal value, so it picks one (for `trust_zone`, the reading that yields a **Boundary Crossing**) and records an Assumption naming the disagreement. That is not a speaker's guess after all: the schema, not the speaker, forces the inference, and the basis says so.
- **Threat** — a STRIDE finding. Always traceable to the Element(s) it affects.
- **Analyst** — one of six parallel agents, each owning a single STRIDE category across all applicable Elements. Drafts complete threat entries (description, element refs, severity, mitigations).
- **Critic** — the single strong-model agent that reviews the merged union of analyst output in one pass: per-threat Verdicts, cross-category dedupe, severity calibration. Grounded in System Model facts, never free-form reflection.
- **Verdict** — the critic's per-threat ruling: confirm, reject (with reason, kept for audit), or needs-info (kept, flagged, tied to unknown attributes).
- **Valid System Model** — one that passes the mechanical well-formedness gate (unique typed IDs, referential integrity, zone membership, legal enum values). Analysts only ever see valid models. An invalid extraction gets one Repair Pass — validator errors fed back to a repair node on the same tier — then the job is **rejected**, carrying the validator's issues. Rejected, not *failed*: the input never became a valid model, which is the submitter's to fix, whereas a failure is ours. Never silent auto-repair.
- **Source** — one piece of untrusted input text a job is built from: a `kind`, a caller-supplied `label`, and the `text` itself. A job carries an ordered, non-empty list of them, replacing the single `description` of earlier versions; a transcript-only job is a one-element list with no special case. `kind` is a closed vocabulary (`description`, `transcript`) and is **load-bearing** — it selects the guidance the extraction prompt renders around that source's text, so adding a kind means changing the prompt and the enum together. `label` is unique within a job, at most 200 characters, and visible to the model, and is the key a **Source Excerpt** cites, keeping the traceability chain (threat → element → the user's own words → which source) intact across N sources. Order is presentation order only: the contract makes no authority claim, so an earlier source does not override a later one. A job is bounded in **UTF-8 bytes** rather than tokens — a token cap would make the contract depend on which vendor a **Deployment**'s tiers select — by a total across all sources and a source count, both deployment config; there is no per-source byte cap, so an over-budget submission is the *sum*'s fault and the error names no single source. A source reaches a model only inside a delimiter it cannot forge — one fenced block per source, sized to the content so no submitted text can close its own block, carrying the `label` *inside* the fence so nothing caller-controlled ever sits in instruction position. That render is a pure function of the job, produced once where the graph is driven, so the service and the eval harness cannot show the same job to a model differently.
- **Source Excerpt** — a short quote from the user's input text that an Element was extracted from. Carried by every Element for traceability (threat → element → user's own words → which **Source** spoke them) and extraction evals. It travels with a `source_label` naming the Source the *quote* came from — the excerpt, not the element, since one verbatim quote has exactly one origin and an element may draw on several; where two Sources disagree the element quotes one claim and the disagreement stays in `notes`. The label is required whenever an excerpt is present and must be one of the job's labels: a citation that does not resolve asserts a traceability chain that is not there, so the validity gate checks it. An optional `source_speaker` names who spoke the quote where the text attributes it — provenance on a quote, never a role and never a claim an analyst weighs — kept as its own field so a name can be stripped, which it cannot be once quoted inside the excerpt.
- **Element ID** — a typed, human-readable slug, unique within one System Model (one job): `<type>:<normalized-name>`, e.g. `process:auth-service`. Data Flows use `flow:<source>-to-<dest>:<label>`. Threats reference Elements by these IDs.
- **Graph Run** — one drive of a built pipeline to completion: the final session state plus one record per **node execution** (which node, the build that served it, its generation-identity fingerprint, its duration). The graph has exactly two drivers — the service over a job, the eval harness over a corpus case — and both obtain a Graph Run from the same place, so provenance never depends on which one ran. A node that executes twice, the critic on a revise path, contributes two records; a deterministic FunctionNode contributes one carrying no model. Distinct from the **Report**: a Graph Run is what happened, the report is what is served, and the run's identity fields (job ID, system name, timestamps) come from the driver rather than the graph.
- **Generation Identity** — what a fingerprint hashes: the **served** build (the identifier the provider says answered, vendor-prefixed, e.g. `vertex_ai/claude-opus-5`) joined to its tier's resolved sampling params. It is a property of the **Model Tier**, not of a graph node: the node name is not an input, so two nodes on one tier served the same build share one generation identity. Read per node *execution*, so a build that moves mid-run yields two identities for one node — the drift signal, not a defect.
- **Deployment** — one installation of this service together with the configuration it runs on: the four files (`model_tiers.toml`, `sampling.toml`, `resilience.toml`, `blessed-fingerprints.toml`) plus the skills and prompts, each located by a `STRIDE_*` variable that picks *which* file is read and never layers a second one over it. Resolved **once per process** and shared by everything that runs analysis, so the HTTP service, the first-run app and an eval sweep cannot silently sit on different configurations of the same install, and the manifest a job is certified against is the same object the report route enforces — by construction, not by two loads agreeing. Loading fails closed: a deployment either has a usable configuration or refuses to start. Its credentials are *not* part of it, being derived from the vendor each **Model Tier** selects.
- **Blessed** — a Generation Identity recorded in a deployment's `config/blessed-fingerprints.toml` because a sanctioned, measured run produced it. Keyed by tier. The list is deployment-local and ships empty; nothing in this repo is blessed on anyone's behalf.
- **Certification** — the three-state result of checking a run's Generation Identities against that blessed list: **certified** (every observed fingerprint is blessed), **uncertified** (at least one is not, reported by node and hash), **unexercised** (a tier the built graph declares presented no fingerprint at all). One function with two callers — the eval CLI over a sweep, and the **service** over each job it completes — so it is not "the eval gate's" result. *Unexercised* is an internal assertion rather than a routine outcome: every tier has a node that always runs, and a run producing no report is never certified. Certification never rides the report. The report carries the raw fingerprints, which are evidence and recomputable from the report alone; certification is a claim about one *deployment's* list and lives on the job record. Never called a "verdict" — that word belongs to the Critic.
- **Model Tier** — one of exactly two vendor-neutral capability classes every LLM node runs on: **`base`** (the workhorse: extraction and repair) and **`strong`** (judgement: the six analysts, the critic, and the recritic re-ask). Names are on a capability axis, not a vendor's product line — `strong` matches the critic's "strong-model" description; the prior `flash`/`pro` were Gemini product names. Each tier independently selects its `(vendor, model)`, so `base` and `strong` may run different vendors at once. Auth is *derived* from the vendor, never configured alongside it — each vendor owns its credential mode, so an unrepresentable pairing like `vertex + api_key` cannot be written down.

# Context

Glossary for the STRIDE threat-modeling service. The canonical system model is the extraction agent's output and every downstream agent's input.

## Glossary

- **System Model** — the canonical, structured representation of the system under analysis, produced by the extraction agent from semi-structured front-end text. The single source all category agents consume.
- **Element** — any node or edge in the System Model. Exactly five types (classic DFD-based STRIDE-per-element taxonomy): External Entity, Process, Data Store, Data Flow, Trust Boundary.
- **External Entity** — an actor outside the system's control: users, third-party systems.
- **Process** — running code or a component that transforms data.
- **Data Store** — where data rests: databases, buckets, queues-at-rest.
- **Data Flow** — a directed connection carrying data between two elements. One flow per interaction; direction = who initiates, the response rides implicitly. An independent reverse-direction interaction (webhook, push) is its own flow.
- **Trust Boundary** — a named trust zone (flat, no nesting): network zones, auth boundaries, privilege levels. Every External Entity, Process, and Data Store belongs to exactly one zone via `trust_zone`.
- **Boundary Crossing** — a derived fact, never extracted: a Data Flow crosses a boundary iff its endpoints' zones differ. The highest-signal STRIDE input, computed mechanically so it cannot contradict the model.
- **Candidate** — a structural condition a deterministic rule found in the validated System Model and handed to one **Category Agent** as something to investigate: a rule ID, the elements it is about, and the model facts that made it fire. Derived like a **Boundary Crossing** and standing far below one. A candidate is **not evidence and cannot become a Threat**: it carries no severity, no attacker action and no claim that anything is wrong, nothing downstream of the prompt reads one, and it is never a **Ground** — a threat a candidate led to is grounded in the crossing or the `unknown` attribute the rule read, never in the rule. Rules fire on structure only (a control attribute's leading token, a zone kind, a fan-in count), so nothing here interprets prose. Investigating a candidate and rejecting it is the intended outcome, and an agent finding a threat no rule triggered on is the reason the agent exists.
- **Asset** — something worth protecting. Not an element type: modeled as tags on Elements from a small controlled vocabulary (`credentials`, `pii`, `financial`, `health`, `secrets`, `business-critical-data`, `availability-critical`, `reputation`; config-extendable). Feeds impact scoring and skill selection; system-specific detail lives in the element's own name/description.
- **Unknown** — a legal attribute value meaning the input neither stated nor allowed inference of a fact. A category agent treats an unknown security control as unverified, never as present or absent. Uncertainty a speaker *voices* — a hedged value ("I think it's OIDC") or an admitted gap ("no idea") — is also `unknown`, not a value and not an **Assumption**: speaking about a fact is not stating it. Their words are kept verbatim in the element's `notes`, which is what distinguishes a gap someone probed from a topic nobody raised. Two **Sources** that disagree land here too wherever the attribute can hold it: equal weight means a disagreement is recorded rather than adjudicated, so the value is `unknown` and both claims are quoted verbatim in `notes` beside their labels. What `notes` carries either way is context for the question a needs-info **Verdict** asks — never evidence for a **Threat**, and never weight on a rating: an unknown attribute rates identically whether someone hedged about it, two people contradicted each other, or nobody raised it at all.
- **Assumption** — a value extraction inferred with a stated basis. Recorded on the System Model's top-level assumptions list (assumption, element ID, basis) as well as in the attribute itself. Unknown = not stated; Assumption = inferred on the record. Never a silent guess — and never a *speaker's* guess: the basis is what extraction inferred from what the input supports, so a hedge is never one. That distinction is invisible downstream if it is got wrong, because a category agent weighs an assumption's value as read from the text. One case arises from the schema rather than from the text: where two **Sources** disagree on an attribute that *cannot* hold `unknown` — a `trust_zone`, an External Entity's `kind`, a Data Flow's endpoints — extraction must still emit a legal value, so it picks one (for `trust_zone`, the reading that yields a **Boundary Crossing**) and records an Assumption naming the disagreement. That is not a speaker's guess after all: the schema, not the speaker, forces the inference, and the basis says so.
- **Threat** — a STRIDE finding. Always traceable to the Element(s) it affects, and to the **Grounds** that justify raising it.
- **Ground** — one piece of justification for one **Threat**, in exactly one of three kinds: a `quote` (verbatim submitter words plus the `source_label` naming the **Source** they came from), an `unknown-attribute` (an element ID plus the attribute whose `unknown` value is what makes the threat raisable), or a `derived-fact` (a flow ID whose **Boundary Crossing** is the fact relied on — a reference, never a copy, since the crossing recomputes from the model the report already embeds). Every threat carries at least one; there is no free-text kind, because free text would be the escape hatch reached for exactly when neither a quote nor an unknown exists. **Chosen by a Category Agent, constructed by the service**: the agent names an **Evidence Reference** or proposes a quote, and code builds the record, so a ground's kind and its fields can never disagree. Never derived from the affected elements' **Source Excerpts** either: an excerpt says why an *element* exists, a ground says why a *threat* was raised, and a derived citation would always render *a* quote and frequently the wrong one. A quote ground is checked mechanically against the bytes of the source it names — presence only, never support, which stays the Critic's judgement — and an unverifiable quote is **marked, not dropped**: the mark lives on the report beside the threat rather than inside the Ground, because a field an agent could set about its own honesty is not evidence. A threat where *no* ground verifies fails the job.
- **Evidence Catalog** — every fact a **Category Agent** may cite, enumerated from the **Valid System Model** before analysis: each attribute holding the **Unknown** sentinel, and each **Boundary Crossing**. Derived, never extracted, and derived twice from the same model rather than passed between nodes, so the set an agent chose from and the set its choice is resolved against cannot differ. A catalog entry asserts only *this fact is in the validated system representation* — `authentication is unknown` is catalogable, `authentication is weak` has no way in, and whether a catalogued fact participates in a credible attack stays the agent's judgement and the **Critic**'s to rule on. Quotes are deliberately absent: choosing a span for what it *states* is the judgement no enumeration can make.
- **Evidence Reference** — one catalog entry's stable ID, `unknown:<element-id>:<attribute>` or `crossing:<flow-id>`, built from IDs the model already carries so the same model yields the same IDs on every run. What a **Category Agent** emits in place of a **Ground**: it selects, and the service resolves the ID back into the entry's canonical record. Resolution is exact — no near match and no repair, because inferring which fact an agent *meant* is the guess the closed set exists to remove — and a reference naming nothing is **dropped and marked**, the way an unverifiable quote is: the threat stands on whatever else it cited, and only a threat left with *no* grounds at all fails the fan-in. Agents compose well-formed references to facts the catalog does not hold, and discarding six lanes of analysis to punish one citation error is a trade this system makes nowhere else.
- **Threat Proposal** — what a **Category Agent** actually emits: a finding carrying `evidence_refs` and quote candidates rather than **Grounds**, and a `sequence` rather than a threat ID or a category. Two flat lists a provider's schema compiler can express exactly, where the conditional field relationship inside a `Ground` cannot be, so nothing an agent can put in either is a shape error. The service resolves a proposal into the draft the **Critic** reads; the report's shape is unchanged. The lane is the graph's fact rather than the agent's — one node per category, filled in before any model runs — so the category is stamped and the ID composed from it during resolution, and a draft's category, its ID's letter and the node that produced it agree by construction. Whether a threat *belongs* in the lane it was found in is a different question, about content rather than spelling, and it is the Critic's.
- **Category Agent** — one of six parallel agents, each owning a single STRIDE category across all applicable Elements. Emits **Threat Proposals** — description, element refs, **Evidence References** and quote candidates, severity, mitigations — which the service resolves into drafts. Named for what it does: *analyst* in this repo means the human reading the report, and the graph node names (`analyze_<category>`) and tier config keys (`analyze/<category>`) follow. It reads the job's **Sources** directly and a *stripped* System Model — `source_excerpt`, `source_label` and `source_speaker` are removed from the model rendered to it — so it cannot align a quote to an excerpt it can no longer see. The report still carries the excerpts; the honest cost is that the bytes an agent saw are no longer the bytes the report carries.
- **Domain Pack** — subject-matter reference material about a technology family (`skills/domains/`), selected per job from the System Model's own technology fields and rendered to the **Category Agents** beside their candidates. Analysis knowledge, never evidence: a pack grounds nothing, and caller text decides only *which* repo-authored pack loads, never what one says. Capped per analysis, because loading every pack into every job spends the largest block in the longest prompt on a system nobody submitted.
- **Reference Note** — one document in the local corpus (`knowledge/notes/`) about a single structural condition: when it applies, what to ask about it, and what it may not be used for. Same standing as a **Domain Pack** and selected differently — by the **Candidate** rules that actually fired in a lane, so the material follows this model's leads rather than its technologies, and a lane that triggered nothing receives nothing. Analysis knowledge, never evidence: a note is not a fact about the system under review, is absent from the evidence catalog, and can be cited by nothing.
- **Worked Case** — one document in the local corpus (`knowledge/cases/`) recording a judgement someone already made about *another* system: the architecture pattern, the threat considered, whether it was accepted or rejected, why, and what decided it. Selected by fired rules like a **Reference Note**, and standing with the exemplars — reasoning to follow, never a conclusion to carry across. Cases are **curated and version-controlled, never learned from production runs**: writing back a run's own output would let one model's mistake become the next model's reference. Several end in a rejection on purpose, which is the outcome an exemplar cannot demonstrate.
- **Coverage** — the per-category account of what deterministic analysis offered a lane and how much of it that lane's drafts cite: candidates, boundary crossings, unknown controls and elements, each with a cited count. Computed in code over the **drafts** rather than the ruled threats, and recorded on the report. It exists to separate *examined and cleared* from *never looked at* — and it measures **citation, not attention**: an agent that read a flow and rightly found nothing cites nothing, so the number that means something is the aggregate across a corpus, never one lane on one case. The denominators alone — how many elements, crossings and unstated controls a model holds, and how many of a lane's rules ran and fired — also travel *forwards*, opening each **Category Agent**'s input, because the separation above is one a lane cannot make about itself unless it was told the size of what it was given. Derived from the same three calls as the account behind it rather than recomputed, so the number in the instruction and the number in the report are one fact. The `*_cited` halves cannot go with them: those need drafts that do not exist yet. **Never a quota** — no number there says how many threats exist, and a lane inflating its drafts to fill one has misread it in the direction that costs more than the undercounting it fixes.
- **Critic** — the single strong-model agent that reviews the merged union of the category agents' output in one pass: per-threat Verdicts, cross-category dedupe, severity calibration. Grounded in System Model facts, never free-form reflection — and never in submitter text: it templates against the same stripped model, so the only submitter words it sees are the ones a finding chose to quote.
- **Verdict** — the critic's per-threat ruling: confirm, reject (with reason, kept for audit), or needs-info (kept, flagged, tied to unknown attributes). Those three rules bind the fields to the `status`, which no provider schema can express, so they are checked at the review seam rather than on the way out of the **Critic**: a verdict that breaks one is the recritic re-ask's to fix, exactly like a dropped or duplicated ruling, and only a second failure ends the job. What the critic emits is therefore the unruled shape; the ruled one is built during assembly, so every verdict a report carries satisfies all three by construction.
- **Valid System Model** — one that passes the mechanical well-formedness gate (unique typed IDs, referential integrity, zone membership, legal enum values). Category agents only ever see valid models. An invalid extraction gets one Repair Pass — validator errors fed back to a repair node on the same tier — then the job is **rejected**, carrying the validator's issues. Rejected, not *failed*: the input never became a valid model, which is the submitter's to fix, whereas a failure is ours. Never silent auto-repair.
- **Source** — one piece of untrusted input text a job is built from: a `kind`, a caller-supplied `label`, and the `text` itself. A job carries an ordered, non-empty list of them, replacing the single `description` of earlier versions; a transcript-only job is a one-element list with no special case. `kind` is a closed vocabulary (`description`, `transcript`) and is **load-bearing** — it selects the guidance the extraction prompt renders around that source's text, so adding a kind means changing the prompt and the enum together. `label` is unique within a job, at most 200 characters, and visible to the model, and is the key a **Source Excerpt** cites, keeping the traceability chain (threat → element → the user's own words → which source) intact across N sources. Order is presentation order only: the contract makes no authority claim, so an earlier source does not override a later one. A job is bounded in **UTF-8 bytes** rather than tokens — a token cap would make the contract depend on which vendor a **Deployment**'s tiers select — by a total across all sources and a source count, both deployment config; there is no per-source byte cap, so an over-budget submission is the *sum*'s fault and the error names no single source. A source reaches a model only inside a delimiter it cannot forge — one fenced block per source, sized to the content so no submitted text can close its own block, carrying the `label` *inside* the fence so nothing caller-controlled ever sits in instruction position. That render is a pure function of the job, produced once where the graph is driven, so the service and the eval harness cannot show the same job to a model differently.
- **Source Excerpt** — a short quote from the user's input text that an Element was extracted from. Carried by every Element for traceability (threat → element → user's own words → which **Source** spoke them) and extraction evals. It travels with a `source_label` naming the Source the *quote* came from — the excerpt, not the element, since one verbatim quote has exactly one origin and an element may draw on several; where two Sources disagree the element quotes one claim and the disagreement stays in `notes`. The label is required whenever an excerpt is present and must be one of the job's labels: a citation that does not resolve asserts a traceability chain that is not there, so the validity gate checks it. An optional `source_speaker` names who spoke the quote where the text attributes it — provenance on a quote, never a role and never a claim a category agent weighs — kept as its own field so a name can be stripped, which it cannot be once quoted inside the excerpt. All three fields are stripped from the model the category agents and the Critic read: an excerpt answers why an element exists, which is a different question from why a threat was raised, and that second one is a **Ground**'s.
- **Element ID** — a typed, human-readable slug, unique within one System Model (one job): `<type>:<normalized-name>`, e.g. `process:auth-service`. Data Flows use `flow:<source>-to-<dest>:<label>`. Threats reference Elements by these IDs.
- **Graph Run** — one drive of a built pipeline to completion: the final session state plus one record per **node execution** (which node, the build that served it, its generation-identity fingerprint, its duration). The graph has exactly two drivers — the service over a job, the eval harness over a corpus case — and both obtain a Graph Run from the same place, so provenance never depends on which one ran. The graph cannot loop, so one drive contributes at most one record per node; a deterministic FunctionNode contributes one carrying no model. Several drives accumulated together — an eval sweep over its corpus — are where one node name carries several records. Distinct from the **Report**: a Graph Run is what happened, the report is what is served, and the run's identity fields (job ID, system name, timestamps) come from the driver rather than the graph.
- **Analysis Context** — the third thing a report records about a run, beside what each node *ran on* (**Generation Identity**) and what each finding *rests on* (**Ground**): what the service put in front of the **Category Agents**. Four parts — a digest of every LLM node's composed instruction, the domain packs this job's model earned, the **Candidate** rules that fired, and the **Reference Note** and **Worked Case** documents those rules retrieved. The digest is taken with the job-varying placeholders unexpanded, so it identifies the repo-authored text and carries no submitted bytes; the submission's own digest is separate, and a Generation Identity says nothing about instructions at all, so two runs can share one and have been told different things. **It is context, never evidence**, and reading it as support for a threat is reading it backwards: a pack named here grounded nothing, a rule named here found nothing, and a document named here proves nothing. Recorded rather than gated — widening certification to the instructions would re-baseline every blessed pair on a prompt edit, which is a decision about what a deployment sanctions rather than a fact about a run.
- **Generation Identity** — what a fingerprint hashes: the **served** build (the identifier the provider says answered, vendor-prefixed, e.g. `vertex_ai/claude-opus-5`) joined to its tier's resolved sampling params. It is a property of the **Model Tier**, not of a graph node: the node name is not an input, so two nodes on one tier served the same build share one generation identity. Read per node *execution*, so a build that moves partway through an eval sweep yields two identities for one node — the drift signal, not a defect.
- **Deployment** — one installation of this service together with the configuration it runs on: the four files (`model_tiers.toml`, `sampling.toml`, `resilience.toml`, `blessed-fingerprints.toml`) plus the skills and prompts, each located by a `STRIDE_*` variable that picks *which* file is read and never layers a second one over it. Resolved **once per process** and shared by everything that runs analysis, so the HTTP service, the first-run app and an eval sweep cannot silently sit on different configurations of the same install, and the manifest a job is certified against is the same object the report route enforces — by construction, not by two loads agreeing. Loading fails closed: a deployment either has a usable configuration or refuses to start. Its credentials are *not* part of it, being derived from the vendor each **Model Tier** selects.
- **Blessed** — a Generation Identity recorded in a deployment's `config/blessed-fingerprints.toml` because a sanctioned, measured run produced it. Keyed by tier. The list is deployment-local and ships empty; nothing in this repo is blessed on anyone's behalf.
- **Promotion** — the write half of Certification: taking a reviewed eval sweep and recording, in this **Deployment**'s files, the configuration it measured (`sampling.toml`, re-pinned in place) and the Generation Identities that configuration produced (`blessed-fingerprints.toml`). Its inputs are **observations, never assertions**. Every fingerprint is recomputed from the served build the sweep saw and the sampling it resolved, both read out of the run artifact's provenance block, so an operator can neither supply a fingerprint directly nor have the *requested* route stand in for the build that answered — the two are different claims, and provider-side routing is what makes the difference matter. Where one tier was answered by more than one build, promotion refuses and asks which to bless rather than choosing; the choice selects among what was observed and cannot introduce anything else. Additive: a blessed identity stays blessed until a human removes it.
- **Certification** — the three-state result of checking a run's Generation Identities against that blessed list: **certified** (every observed fingerprint is blessed), **uncertified** (at least one is not, reported by node and hash), **unexercised** (a tier the built graph declares presented no fingerprint at all). One function with two callers — the eval CLI over a sweep, and the **service** over each job it completes — so it is not "the eval gate's" result. *Unexercised* is an internal assertion rather than a routine outcome: every tier has a node that always runs, and a run producing no report is never certified. Certification never rides the report. The report carries the raw fingerprints, which are evidence and recomputable from the report alone; certification is a claim about one *deployment's* list and lives on the job record. Never called a "verdict" — that word belongs to the Critic.
- **Model Tier** — one of exactly two vendor-neutral capability classes every LLM node runs on: **`base`** (the workhorse: extraction and repair) and **`strong`** (judgement: the six category agents, the critic, and the recritic re-ask). Names are on a capability axis, not a vendor's product line — `strong` matches the critic's "strong-model" description; the prior `flash`/`pro` were Gemini product names. Each tier independently selects its `(vendor, model)`, so `base` and `strong` may run different vendors at once. Auth is *derived* from the vendor, never configured alongside it — each vendor owns its credential mode, so an unrepresentable pairing like `vertex + api_key` cannot be written down.
- **Provider Capability** — what one `(vendor, model)` pair will accept, in exactly three states: **supported** (the provider accepts it, and the pinned model map is what says so), **unsupported** (the provider rejects it), **unknown** (the pinned map carries no entry for the model, so nothing here has an answer). The third state is the load-bearing one and is never collapsed into the second: LiteLLM answers for an unmapped model out of the provider's *base* config rather than declining, so "rejected" and "never heard of it" reach a raise/no-raise gate as the same non-raise. That fallback is correct for a **Model Gate**, whose job is to refuse a binding rather than to know things, and becomes a false assurance the moment it is reported as a checked answer. A pair reporting `unknown` still binds — refusing to run a model the map has not caught up with is the worse failure — but nothing has verified it. Capabilities legitimately differ between providers and are never equalised: inventing a default for an unsupported control, or emulating one without disclosure, is the failure this vocabulary exists to name.
- **Provider Conformance** — whether the *application* behaves equivalently on a given provider, which is a different question from how good that provider's threat models are. Conformance is deterministic, is asserted for every supported vendor equally, and covers binding, the build-time gates, sampling resolution, **Generation Identity**, and the report schema; **model quality** is empirical, lives in `evals/`, and is expected to differ. A vendor never fails conformance for scoring lower than another. The suite is **credential-free** by construction — capabilities come from the pinned model map and bindings are built against a declared-but-fake environment — which is what lets it run for all three vendors in the offline lane rather than only where credentials happen to exist. Its limit is exactly as important as its coverage: it establishes what a provider *would be asked for*, never that a provider has served a request. Answering that second question is the **Provider Smoke**'s job, and where its credentials are absent the coverage remains **unexercised** in the sense Certification already gives the word, reported as such rather than left to a green check to imply.
- **Provider Smoke** — one small system, once, through the shipped graph, on the pair a deployment selects: the cheapest run that can show a provider actually served this application. It answers eight questions and no others — binding, structured extraction, analyst and critic output, sampling acceptance, served-model capture, **Generation Identity**, and a provenance record that recomputes from itself — and it answers them for every supported vendor on the same trigger, because coverage that exists only where credentials happen to exist is how one vendor comes to be better assured than the others. Its answers are three-valued for the same reason **Provider Capability**'s are: a question the provider left unanswered (a response carrying no served build) reports `unknown` and fails nothing, since the application handled the difference correctly. It is not an eval and never grades a threat model — a vendor whose analysis is weaker passes the smoke, and a vendor that has not run one is unexercised rather than failing.

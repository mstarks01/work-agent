# QA-2026-10-13-02: why a full description still meets about 75 answers, and one place for each question kind

The maintainer ran the example description with STRIDE only and met 80 and 76
answers before the analysis, with 126 and 131 optional questions. This audit
reads where they come from and measures the order that lists each question kind
once. E1 to E3 are offline (`ANALYSIS_OFFLINE=1`) and spend $0. E4 spent about
$0.10 of a grant of six head-only runs on OpenAI's base tier.

## What a full description leaves (E4)

`head_run.py` runs the example to the questions stage (extraction, repair and
the assertion pass, all on the base tier, `gpt-5.6-luna`) and reads the list
the page would show. Each run cost about $0.024.

| Run | Text | Questions | Choices | Link questions | Attribute questions |
| --- | --- | --- | --- | --- | --- |
| 1 | #1644's example | 30 | 75 | 3 | 6 |
| 2 | the audit log described | 30 (9 held back) | 59 | 4 | 7 |
| 3 | the platform team's access in one sentence | rejected by the validity gate; issues not recorded | | | |
| 4 | the same, two words shorter | 26 | 70 | 2 | 3 |

Extraction records nearly every stated control. What stays is not the
description's to close:

- About 23 question kinds in every run ("Who may do what on…", "What limits
  bound…", "What record shows…"). A kind is always open (`_open_key`), so the
  Orders API is asked its limits though the example states 100 requests a
  minute. With every unknown attribute of run 1 filled in offline, 18 kinds and
  56 choices remain.
- The link questions name people the model already holds as elements
  (`entity:analytics-team`, `entity:platform-team`,
  `entity:support-administrator`). #1649 offers the matching element.
- A sentence about who may reach a thing becomes a connection, and the
  connection needs its own controls: run 2's "only the platform team can…"
  phrases added six attribute questions.

The choice totals move by up to 16 between runs of one text.

## The early-answerers walk cannot see a group order (E1)

`run.py early-answerers` answers the first listed question, saves and reads the
list again. Keeping a kind's rows together never moves the first row, so the
grouped order gives the same 15,696 readings, byte for byte, as the shipped
order (`QA-2026-10-12-02/early-answerers-walks.json`). This instrument cannot
price an order that moves only later rows.

## Every group gathered: refuted with both frameworks (E2)

`run.py early-policies` walks down the list as shown, every answer "I don't
know". The shipped order's reading is `QA-2026-10-12-02/early-policies-adaptive.json`
(reproduced byte for byte). `early-policies-grouped-all.json` gathers every
group, capabilities included:

| `shipped-list` | 5 choices | 10 | 15 | 20 | 30 |
| --- | --- | --- | --- | --- | --- |
| STRIDE alone, completed | 946 → 1,132 | 1,488 → 1,538 | 1,773 → 1,807 | 1,939 → 2,044 | 2,073 → 2,119 |
| STRIDE with ASVS, completed | 1,009 → 60 | 1,555 → 75 | 1,812 → 716 | 2,019 → 1,048 | 2,098 → 1,280 |
| ASVS with STRIDE, settled | 174 → 780 | 218 → 1,248 | 629 → 1,446 | 924 → 1,536 | 1,282 → 1,716 |

Every capability shares one group, so the first capability pulls all of them
ahead of STRIDE's questions, and the frameworks' turns are lost.

## The question kinds gathered, capabilities in place: supported (E3)

`early-policies-grouped-kinds.json` keeps each capability question where its
turn puts it and gathers every other group:

| `shipped-list` | 5 choices | 10 | 15 | 20 | 30 |
| --- | --- | --- | --- | --- | --- |
| STRIDE alone, completed | +19.7% | +3.4% | +1.9% | +5.4% | +2.2% |
| STRIDE with ASVS, completed | +0.8% | −3.9% | +4.6% | +2.0% | +0.6% |
| ASVS alone, settled | 0 | 0 | 0 | 0 | 0 |
| ASVS with STRIDE, settled | −6.9% | −15.6% | −11.0% | −21.8% | −12.6% |

The walk charges each row its own choices. A kind's rows in one box share a
"Same for all" control, so the grouped order costs fewer choices than the walk
counts. On the three head runs the page draws 9, 8 and 6 boxes where it drew
17, 23 and 18, one for each kind. The maintainer chose this order on
2026-10-13 (ADR 0080).

## The head-run script (E4)

Run from the repository root in a login shell, with `ANALYSIS_TIERS_FILE`
naming a tier file whose base tier is `gpt-5.6-luna` on `openai`:
`uv run python head_run.py <label> '{"stride": {}}' <out-dir>`.

```python
"""Run the example to the questions stage, save the checkpoint, and summarise the list."""
import asyncio, collections, json, sys, time
from pathlib import Path
from analysis_service.answer_round import question_set
from analysis_service.answer_sets import AnswerSet
from analysis_service.engine import Engine
from analysis_service.jobs import PipelineAwaiting
from analysis_service.report import FrameworkSelection
from analysis_service.sources import Source

label, frameworks_json = sys.argv[1], sys.argv[2]
out = Path(sys.argv[3])
frameworks = json.loads(frameworks_json)
selection = [FrameworkSelection(name=n, options=o) for n, o in frameworks.items()]
engine = Engine.from_config(selection)
text = Path("examples/orders.md").read_text(encoding="utf-8")
start = time.monotonic()
outcome = asyncio.run(engine.analyze([Source.description(text, label="Pasted description")],
                                     system_name="Orders", ask_questions=True))
if not isinstance(outcome, PipelineAwaiting):
    for issue in getattr(outcome, "issues", []):
        print("ISSUE", issue.code, "|", issue.message[:300])
    (out / f"{label}.nodes.json").write_text(json.dumps([n.model_dump(mode="json") for n in outcome.nodes], indent=1))
    raise SystemExit(f"{label}: {type(outcome).__name__}")
(out / f"{label}.checkpoint.json").write_text(outcome.checkpoint.model_dump_json(indent=1))
(out / f"{label}.nodes.json").write_text(json.dumps([n.model_dump(mode="json") for n in outcome.nodes], indent=1))
cp = outcome.checkpoint
qs = question_set(cp.system_model, None if cp.assertions is None else cp.assertions.catalog,
                  frameworks, [], waiting=True, answered=AnswerSet(), final=False, shown=[])
kinds = collections.Counter("gate" if q.gates else q.kind for q in qs.early)
groups = collections.Counter(q.group for q in qs.early)
print(f"{label}: {time.monotonic() - start:.0f}s, elements {len(list(cp.system_model.elements()))}")
print(f"  list {len(qs.early)} questions, {sum(q.decisions for q in qs.early)} choices; links {len(qs.links)};"
      f" more {len(qs.held_back) + len(qs.below_floor)} (held_back {len(qs.held_back)}, below_floor {len(qs.below_floor)})")
print("  by kind:", dict(kinds))
print("  by group:", dict(groups.most_common()))
for n in outcome.nodes:
    d = n.model_dump(mode="json")
    print("  node", d.get("node"), {k: v for k, v in d.items() if "token" in k or k in ("served_model", "cost_usd", "charge")})
```

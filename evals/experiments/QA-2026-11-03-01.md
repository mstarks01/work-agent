# QA-2026-11-03-01: does a lane state the ruled attacker position?

#2141 gave each STRIDE draft an attacker position, and #2145 recorded the
maintainer's position on 94 must-finds. No archived draft states a position,
so only fresh lane output can show if the lanes state the ruled one. Mode
audit. Three grants of $1 each, $3.00 in all. The provider reported $0.7540
for stage 1, $0.7786 for stage 2 and $0.8100 for stage 3, so $2.3426 in all.
Revision `d51830a1`.

`QA-2026-11-03-01/design.md` holds the question, the definitions, each
falsifier and the decision table. Each stage's section was written before
that stage's first call. Stage 1 named the `signed` arm for every case, and
before any call it was changed to the `none` arm for cases 14 and 15, which
have no `facts.json`.

## The failure, the mechanism and the competing explanations

The failure E1 found is in `runs/id-read.json`: five ruled `outside` reads of
a store, stated as `storage-copy`. Four explanations compete:

1. **The label:** the lane writes the grant-holder read and labels it
   `storage-copy`. E2 tests this with a definition sentence.
2. **The omission:** the lane writes no grant-holder read at all, so only its
   storage-copy draft reaches the reference. E3 tests this with an exemplar.
3. **The place:** the lane writes the read, but at another flow, and the
   scorer's place rule does not match it.
4. **The ruling:** the references describe a grant that the sources do not
   state, so a lane that reads only the sources has no attacker to write.

QA-2026-09-26-01-E3 refuted a completeness sentence on this pattern (02/6,
05/6, 05/7, 12/8) before drafts stated a position: each draft read a storage
copy, and none a read grant. The ledger search before E2 used other words and
missed that row, so E2 repeats a fix of its class.

QA-2026-10-05-02-E3 supported the `information-disclosure-store-readers`
lead, which asks "Who else holds a grant like a reader's": with it, the lane
stated the access-path threat at 02/6 and 12/8 in 4 of 8 places, against 1
of 8 without. That lead is on `main`. The five E1 misses fall on five
stores, and today's prepare fires the lead at four of them: the telemetry
lake of 02/6 (reader `entity:fleet-operator`), the Redis feature store of
04/9 (`process:model-server`), the file share of 11/10
(`entity:payroll-system`) and the landing bucket of 12/8
(`process:supplier-master-service`). It does not fire at the inference log of
04/8, which has no stated reader. So at 02/6 and 12/8 the sources name a
reader, the lead asks about other grant holders, and the lane still writes no
grant-holder read.

## E2: a definition sentence, estimated $0.75, $0.7786

`sentence.patch` adds one sentence after the `storage-copy` definition in
`frameworks/stride/output.md`: a read through the store's own access is
`outside`. Four of the five misses repeat with the same stated position. Only
04/9 changed. The `outside` rate is 2 of 6, which passes the falsifier's 2 in
7 only because 14/4, which agreed in E1, was not reached. E2 is inconclusive,
and the sentence is not applied.

The drafts show the cause. At 02/6, 04/8 and 12/8 the lane writes a
storage-copy read of the store, and sometimes a compromised-reader read, but
no read by an attacker who holds a grant on the store. At 11/10 it also writes
an `outside` read of the file share, but on the collect flow, and the
reference names the write flow, so the scorer does not match it. Every `read`
of a store in the exemplars is one of those two. Exemplar 2 shows a password
holder, but with the verb `recover-credential`.

each option carried the author's reason. The maintainer's choices:

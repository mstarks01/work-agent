## E1: almost no reference claim rests on a fact no predicate can hold

All 331 reference claims of the 13 tuned cases were read against each case's
source. For each claim, the reading names the fact the claim rests on and what
holds it.

| Class | All claims | Must-finds |
|---|---:|---:|
| `silent`: the source never states the fact | 222 | 88 |
| `predicate`: a registered predicate holds it | 52 | 36 |
| `field`: a System Model attribute holds it | 39 | 23 |
| `structure`: the topology alone | 17 | 6 |
| `none`: stated, and nothing holds it | 1 | 0 |

Two thirds of the claims rest on silence, and a predicate cannot help a claim
the source gives no fact for. Every stated fact but one already has a holder.

**The one fact.** In case 08, group membership and leavers reach the directory
only through a nightly pull. Claim 08 stride 16 rests on it, and claims 08
stride 19 and 08 asvs 2 rest on it in part. The value is a delay in words, so a
predicate for it would reach a lane as evidence and would have no rule.

**Three signed rows may understate their source.** A sitting decides each:

- Case 04: "we have never expired one", while `credential-expiry` and
  `credential-rotation` on the API key read `unknown`.
- Case 04: "Redis has no password on it", while `authentication-mechanism` on
  the feature-store flow reads `unknown`.
- Case 10: the admin reaches the database "from wherever they happen to be —
  there is no jump host", and no row states the database's exposure.

**What this does not measure.** It reads only facts that some reference claim
rests on. A stated fact that no claim uses is not counted. And a predicate that
exists may still go unwritten by the `assert` node, which required-fact recall
measures.

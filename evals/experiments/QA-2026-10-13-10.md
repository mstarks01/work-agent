# QA-2026-10-13-10: capabilities that closed fields of the model prove

Since ADR 0084, one choice answers "no" to the capability questions left, so
a page's choices are mostly its "yes" answers. This audit measured what code
removes when it states a capability present where a closed field of the model
proves it (ADR 0085). It spent nothing.

## The rows

A prototype read 26 rows that hold by definition. Nine fired on none of the
58 distinct archived models (`webrtc`, `graphql`, `ldap`, `mail-sending`,
`mutual-tls`, `authentication`, the two HTTP/3 rows and `oauth`), and the
maintainer rejected them on 2026-10-13. The other 17 are
`analysis_service.field_capabilities.FIELD_CAPABILITIES`. The maintainer
chose that the owner is not asked about a capability code states: a wrong
"present" only makes a requirement apply.

## The measurement (E1)

The script below reads the example's model from `QA-2026-10-13-08`'s
checkpoint, and each distinct system model under the main checkout's
`evals/` (58), with and without the rows. Its output is
`QA-2026-10-13-10/field-capabilities.json`.

| ASVS level | Capability questions listed | Off the list | Units applicable with no answer |
| --- | --- | --- | --- |
| 1 | 10 → 8 | 24 → 22 | 7 → 13 |
| 2 | 30 → 30 | 77 → 67 | 39 → 59 |
| 3 | 30 → 30 | 111 → 100 | 47 → 79 |

At levels 2 and 3, four questions the example's owner answers "yes" leave the
list (`tls-use`, `encryption`, `external-facing-http-services`,
`sensitive-http-requests`), and the limit of 30 fills it from below.

Across the 58 archived models, the rows make 118 units applicable at level 1,
551 at level 2 and 927 at level 3. How often each row fires:

| Row | Models |
| --- | --- |
| `sensitive-data` | 57 |
| `external-facing-http-services` | 33 |
| `secret-assets` | 25 |
| `tls-use`, `cryptographic-operations`, `cryptographic-keys` | 18 each |
| `separate-service-connections` | 11 |
| `sensitive-http-requests` | 10 |
| `http2-messages`, `http2-request-reception`, `encryption` | 9 each |
| `tls-client`, `internal-http-connections` | 6 each |
| `internal-tls-connections`, `websocket`, `xml-parsing` | 3 each |
| `internal-services` | 2 |

The measurement reads what the rows state, not whether it is true: a wrong
asset tag states a capability the application lacks, and that rate is
unmeasured.

## The script

```python
"""Lever A's effect: the example's page and units, and the archive."""
import collections
import json
import sys
from pathlib import Path

from analysis_service.answer_round import question_set
from analysis_service.answer_sets import AnswerSet
from analysis_service.field_capabilities import with_field_capabilities
from analysis_service.frameworks import PACKAGES
from analysis_service.jobs import Checkpoint
from analysis_service.report import Report


def listed(model, level):
    qs = question_set(model, None, {"asvs": {"level": level}}, [], waiting=True,
                      answered=AnswerSet(), final=False, shown=[])
    on = [q for q in qs.early if q.kind == "capability"]
    off = [q for q in (*qs.held_back, *qs.below_floor) if q.kind == "capability"]
    return len(on), len(off), {q.key[-1] for q in on}


def units(model, level):
    entries = PACKAGES["asvs"].record.applicability(model, {"level": level})
    return collections.Counter(e.state for e in entries)


out = {"example": {}, "archive": {}}
cp = Checkpoint.model_validate_json(Path(sys.argv[1]).read_text())
before, after = cp.system_model, with_field_capabilities(cp.system_model)
for level in (1, 2, 3):
    b, a = listed(before, level), listed(after, level)
    out["example"][f"L{level}"] = {
        "listed": [b[0], a[0]], "off_list": [b[1], a[1]], "left_the_list": sorted(b[2] - a[2]),
        "applicable": [units(before, level)["applicable"], units(after, level)["applicable"]],
        "unknown": [units(before, level)["unknown"], units(after, level)["unknown"]],
    }
fires = collections.Counter()
settled = collections.Counter()
seen = set()
reports = 0
for path in sorted(Path(sys.argv[2]).rglob("*.report.json")):
    report = Report.model_validate_json(path.read_text(encoding="utf-8"))
    key = report.system_model.model_dump_json()
    if key in seen:
        continue
    seen.add(key)
    reports += 1
    model = with_field_capabilities(report.system_model)
    fires.update(s.capability for s in model.capabilities if s.basis)
    for level in (1, 2, 3):
        settled[f"L{level}"] += units(model, level)["applicable"] - units(report.system_model, level)["applicable"]
out["archive"] = {"distinct_models": reports, "fires": dict(fires.most_common()),
                  "units_made_applicable": dict(settled)}
print(json.dumps(out, indent=1))
```

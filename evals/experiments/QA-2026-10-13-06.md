# QA-2026-10-13-06: can a model tell a default that cannot be disabled from one that can

The maintainer asked whether a model, without a table, can decide that a
service or protocol is secure by design and cannot be made insecure, well
enough to skip the clarifying question. The rule was declared before the run:
no false "cannot be disabled" in any run lets the model decide; any such error
limits it to suggesting an answer the owner confirms.

## The key

39 items, each checked against the vendor's or the standard's own
documentation on 2026-10-13: 20 properties that cannot be disabled (S3 new
objects, DynamoDB, CloudWatch Logs, Secrets Manager, Google Cloud Storage,
BigQuery, Azure Blob Storage, managed disks, Cosmos DB, Snowflake at rest and in
transit, Stripe's HTTPS and API key, Auth0's TLS endpoints, API Gateway,
MongoDB Atlas, ElastiCache Serverless, WebRTC, QUIC, WireGuard's peer
authentication); 14 traps that are on by default or optional and can be turned
off (RDS, SQS, EBS, Azure SQL TDE, Azure Storage secure transfer, S3's TLS,
Cloud SQL's TLS, CloudFront's viewer policy, ElastiCache for Redis OSS, Lambda
function URLs, HTTP/2, gRPC, MQTT, SSH client authentication); and 5
self-managed items that are plainly false. Lambda function URLs were first
believed HTTPS-only during the key's own research; AWS documents HTTP and HTTPS.

## The run (E1)

`gpt-5.6-luna` on OpenAI, 8 items a call, 5 runs, $0.064 of a $0.10 grant. Each
answer gives on-by-default, can-disable and a documentation URL; a claim of
"cannot be disabled" is on-by-default and not can-disable. Answers are in
`QA-2026-10-13-06/luna-answers.json`; the script and the key are in the
session's scratchpad and are restated above.

| Per run | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| True properties found (of 20) | 20 | 20 | 20 | 20 | 20 |
| False "cannot be disabled" | 2 | 2 | 3 | 2 | 2 |

The false claims: Lambda function URLs serve only HTTPS (5 of 5 runs), Azure SQL
Database's TDE cannot be disabled (4 of 5), SSH always authenticates the client
(2 of 5). Each cites a documentation URL that does not say so.

By the declared rule the model cannot decide alone: every run would have closed
at least two questions whose true answer can be "no".

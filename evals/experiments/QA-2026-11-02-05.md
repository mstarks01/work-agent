## The ballot

`build_ballot.py` writes `ballot-issued.csv` and `ballot-key.json` from the
run outputs: 59 rows in a fixed shuffled order. They are the 12 case 05 drafts
at the two target config stores and the 10 control drafts at the dispatch
database and `store:inference-log` (E3), and the 37 spoofing drafts (E2). A row
does not show its run: its `group` is a letter for the run, in a second
shuffled order, and the key maps each row to its run. Each row's `verdicts`
column lists its closed set. For E2, `duplicate` marks a draft that repeats
another row of the same group, and `duplicate_of` names that row; a repeat
across groups is expected, because each group is one run. A right E2 draft can share its flow with a right row of the same group. If
that row impersonates the other end, name it in `pair_of`. Return the file as
`ballot-returned.csv` with every other column unchanged. `read_ballot.py`
refuses a changed issued column, a verdict outside its set and a link to a row
of another check or group, and prints the counts the E2 and E3 falsifiers read, with each control counted in each run.
Those counts become the outcomes of E2 and E3 in new rows recorded with
`run.py experiments --record`.

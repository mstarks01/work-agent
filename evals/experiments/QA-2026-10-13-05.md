# QA-2026-10-13-05: the questions luna and terra leave for the example

The maintainer asked how the questions differ when the first part of a job
(extraction, repair and the assertion pass) runs on terra instead of luna.
No archived extraction ran on terra, so this audit ran three head-only runs of
each on the example description, STRIDE only, OpenAI direct, with only the
base tier's model changed (`gpt-5.6-luna` → `gpt-5.6-terra`); the node map and
the sampling stayed. It spent $0.76 of a $0.90 grant. The runs are the same
script as QA-2026-10-13-02's head runs, and the lists are read as the page
asks them after ADR 0081: each group of field questions once.

## The questions (E1)

| Per run, runs 1-3 | luna | terra |
| --- | --- | --- |
| Questions on the page | 6, 6, 6 | 7, 10, 10 |
| Choices on the page | 13, 13, 13 | 14, 18, 18 |
| Element rows under them | 26, 25, 25 | 25, 45, 45 |
| Attribute rows | 2, 2, 2 | 3, 12, 12 |
| Link questions | 4, 3, 4 | 4, 3, 4 |
| Elements | 36, 37, 37 | 34, 35, 34 |
| Cost of the first part | $0.015, $0.014, $0.024 | $0.239, $0.228, $0.235 |

The extra questions come from one reading. Where the example says "over
HTTPS", luna records the connection's `encryption_in_transit` as `HTTPS`, and
terra, in two of three runs, leaves it `unknown` and records only the
protocol: 9 connections, so a whole "Is the connection encrypted?" group, and
with it `reachability`, `stored-copy-integrity` and a zone question.
`prompts/extract.md` does not say whether a protocol that implies encryption
states it, so the two models read the gap differently.

Both models extract about the same model (34 to 37 elements, 14 connections),
and both leave the same six groups of question kinds open.

The six runs' checkpoints and node usage are in `QA-2026-10-13-05/`.

## E1: the archived arm holds no undecidable crossing (#1075)

#1075 asks what a lane does with an undecidable crossing, and how the critic
splits drafts on one (ADR 0039 rule 4). Its triage says the after arm on disk,
Baseline `6bff717`, can answer both halves offline.

It cannot. Counted from each `boundary_crossings` block, with `decided` false:

| Where | Crossings | Undecidable |
| --- | ---: | ---: |
| Baseline `6bff717`, the 29 flows the research note simulates as undecidable | 29 | 0 |
| All 253 archived reports | | 0 |
| Today's corpus `model.json` files | 52 | 0 |
| Extraction, `20260919T-naming-rule` r1 to r3 (38 valid extractions) | 222 | **179** |
| Extraction, `20260918T-placement-rule` after arm (5 runs) | 386 | 305 |
| Extraction, `20260918T-placement-rule` before arm (5 runs) | 331 | 205 |

The corpus models place every component, and 34 of their 52 crossings rest on
an assumed endpoint. An analysis-mode run reads those models, so it never meets
an undecidable crossing. Extraction leaves components unplaced, so an
end-to-end run meets one on about four crossings in five.

**What it means for the decision.**

- Neither half of #1075 can be read from the archive, because no lane or
  critic has ever seen an undecidable crossing.
- The comparison #1075 prices, an analysis-mode sweep either side of the
  prompt change ($31, declined), would measure nothing: neither arm can hold
  an undecidable crossing.
- Rule 4 governs most of the leads an end-to-end job meets, and every
  Baseline so far measures the condition where it never applies. This is the
  gap #742 names in general.

**The narrowest experiment that can see it** is one end-to-end run of one case
on the current prompts. Case 10 carries 11 of the 26 ruled findings, so its
drafts can be compared with the ruling of 2026-09-18. At the measured prices
(extraction about $0.04, analysis about $0.15 to $0.23 a case on luna-pro), one
run costs about $0.25. It needs its own approval.

The script that counted the extraction rows:

```python
import glob, json, collections
from analysis_service.system_model import SystemModel

stats = collections.defaultdict(lambda: [0, 0, 0, 0])
for f in glob.glob("evals/emissions/2026091[89]T-*/**/*.extraction.json", recursive=True):
    run = f.split("/")[2] + "/" + f.split("/")[3].split(".")[0]
    raw = json.load(open(f))["raw"]
    s = stats[run]
    s[0] += 1
    try:
        model = SystemModel.model_validate(raw)
        crossings = model.boundary_crossings()
    except ValueError:
        continue
    s[1] += 1
    s[2] += len(crossings)
    s[3] += sum(1 for c in crossings if not c.decided)
for run, (n, valid, crossings, undecidable) in sorted(stats.items()):
    print(f"{run}: {valid}/{n} valid, {crossings} crossings, {undecidable} undecidable")
```

## E2: which different findings share one claim identity in a run (#1438)

#1438 records one reference pair that merged: two credentials of one client,
both `use-credential` at one place. The question is how often produced drafts
collide that way, and what a fix would separate.

Every STRIDE draft of the four archived Baselines, grouped by lane, verb and
folded place before the critic:

| Family | Keys | Keys holding two drafts |
| --- | ---: | ---: |
| disclosure | 258 | 0 |
| integrity | 207 | 2 |
| identity | 132 | 7 |
| attribution | 84 | 0 |
| availability | 82 | 1 |
| authorization | 71 | 1 |
| credential | 56 | **0** |

All 11 groups hold two different findings. None is a credential pair.

- **5 are `impersonate` in opposite directions** on one flow: a fake server to
  the client, and a fake client to the server.
- **6 differ by access path or channel**, such as a leaked password against an
  offline copy, or a cross-origin request against a WebSocket handshake.

In 9 of the 11, the critic gave the two drafts different verdicts, and both
reached the report.

**What each option would separate.**

| Option | Separates | Cost |
| --- | ---: | --- |
| Add the credential to the identity | 0 of 11 | a new claim field |
| A lint on same-verb collisions | 0 produced | exists already for reference claims (`UNSEPARATED`) |
| Add the impersonated side to the identity | 5 of 11 | a new field the model writes, and a reversal of ADR 0031 |

A flow-derived direction, the one ADR 0031 priced, separates none of the 5:
both drafts of a pair cite the same flow.

**What it means for the decision.** Different findings share a key on 11 of
about 890 keys (1.2%). The credential shape #1438 names does not occur in runs.
No identity change has a ceiling worth a schema change and a paid validation
now.

## E4: what lane-targeted reanalysis would save (#561)

A follow-up runs every lane again (ADR 0044). The idea priced here reruns only
the lanes holding a finding that cites an answered fact, and reuses the other
lanes' drafts.

On the five withheld-and-answered pairs of case 01, three answered
authentication facts were cited in **26 of 30 lanes**. A targeted follow-up
would skip 4 lanes, about 13% of lane calls, and of the 84 findings that moved,
**4 moved in a lane** it would have skipped.

**What it means for the decision.** Answers about common controls reach nearly
every lane, so lane-level reuse saves little and loses findings. Do not build
it on this evidence. Reconsider when real owners' answers (#1286) touch few
lanes of a large selection.
